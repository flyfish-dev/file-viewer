# 赞助 File Viewer

File Viewer 让 Office、PDF/OFD、CAD、压缩包、邮件、3D、音视频和数据文件尽可能留在浏览器内完成预览，避免再次上传文件或额外建设转码服务。公开项目会继续保持 Apache-2.0 开源。

> 如果 File Viewer 为你的团队节省了研发时间、服务器成本或长期兼容维护工作，赞助就是把其中一小部分价值直接投入项目持续维护的方式。

- [通过 GitHub Sponsors 赞助](https://github.com/sponsors/wybaby168?metadata_campaign=file-viewer-docs-zh) — 支持一次性或持续赞助。
- [微信 / 支付宝赞赏](https://dev.flyfish.group/sponsor?source=file-viewer-docs) — 适合国内用户的一次性支持。
- [企业技术支持](https://dev.flyfish.group/shop) — 适用于私有化部署、定制兼容、合同发票和明确响应要求。

## 为什么项目需要赞助

能打开演示文件只是起点。长期维护真正消耗时间的，是那些很难复现和验证的真实业务问题：不同软件生成的 Office 文件、CAD 厂商扩展、损坏或加密压缩包、浏览器回归、Worker 与 WASM 资源路径、嵌入字体、旧框架构建，以及完全离线的部署环境。

赞助的意义，不是把开源功能变成付费功能，而是让这些重要却不显眼的兼容工作能够获得稳定、持续的维护时间，而不是只能等待维护者的零散业余时间。

## 赞助多少比较合适

没有最低金额，也没有固定档位。一次“这次真帮我省事了”的小额赞赏就有价值；持续赞助更有帮助，因为维护时间更容易安排。

按 File Viewer 实际为你节省的时间和麻烦决定即可。如果企业还需要 SLA、合同、发票、敏感文件处理或确定交付，请选择企业技术支持。赞助金额再高，也不会购买公开 issue 的优先级。

## 明确边界

赞助用于支持项目，不是隐藏的付费 issue 排队机制。

- 赞助不保证某个格式、功能或 Bug 一定被接受，也不承诺在指定日期完成。
- 除非公开赞助档位或企业协议中明确包含，否则不提供私下咨询、敏感文件分析或 SLA。
- 赞助不会改变 Apache-2.0 许可，也不会限制任何人使用公开功能和文档。
- 请勿在公开 issue 中上传隐私文件、合同、客户资料或内部文档。应优先提供脱敏样本，或通过明确范围的企业服务进行私下处理。

## 不赞助也可以提供很大帮助

脱敏失败样本、最小复现、准确的问题描述、文档修正、翻译、真实案例，以及把项目分享给真正需要私有文件预览的团队，都会直接提高 File Viewer 的质量。
