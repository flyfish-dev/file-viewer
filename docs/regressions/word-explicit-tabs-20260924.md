# Word 显式制表位的可测量布局

## 根因与修复

预览引擎已输出显式制表位、对齐方式和位置，但无前导符的普通制表符在默认路径中只有一个字符宽。结果是右侧文字并未落在原稿指定的右对齐位置，居中和多制表段也会错误。

新增 `layoutDocxExplicitTabs` 在 Word renderer 的页面尺寸与缩放布局阶段消费已有元数据，按元素所属文档和未缩放坐标计算左／右／居中制表位，只测量下一个制表符、换行或独立绘图之前的同一行文本。重复布局从零宽开始测量，避免缩放与刷新累计偏差。保留原有 NBSP 和运行样式，不改写正文。前导符／目录、竖排／RTL 及不支持的对齐方式不使用此物理坐标近似。

该修复只依赖解析得到的制表属性，不依赖文件名、正文或哈希。没有修改公共 API、运行时依赖、版本、锁文件或引擎分发。

## 原样与回归

C030 原始字节 SHA-256 为 `4b2e9b2519af88f32cec9c4e0622ca7979f5c768c569819d48e26355001cb467`。实际 XML 中目标是宽 8500 twips 的框架段落，不是表格。其右制表位为 425 pt。验收检查右侧文字末端相对于段落内容原点的坐标，而不只是制表符宽度是否改变。

`verify-explicit-tabs.mjs` 默认覆盖 15 项；提供 C030 时为 27 项。实际 Word renderer 在 DPR 1/2 及 100%/50%/200%/88%/100% 往返缩放下检查位置误差，要求低于 1 个未缩放 CSS 像素，并校验 871 个原始正文字符、5 张图片、无原生表格。生成式 OOXML 另外覆盖真实单元格、框架段落、连续制表、左右居中对齐、显式换行和尾部空制表位。13 个单元测试覆盖隐藏容器、重复布局、边框内边距、无效位置与原有路径保护。

```bash
pnpm --filter @file-viewer/core build
pnpm --filter @file-viewer/doc build
pnpm --filter @file-viewer/renderer-word build
WORD_TABS_ORIGINAL=/path/to/C030.docx \
  node packages/renderers/word/scripts/verify-explicit-tabs.mjs
```

测试只读本地原样，报告仅保留中性编号、内容哈希、数量及几何数据；不输出原稿正文。`WORD_TABS_SKIP_SCREENSHOT=1` 可在不能截图的本地浏览器中仅运行数值验收，报告明确记录未截图，不能当作完整截图验收。

## 范围

本组收口所覆盖的显式、非前导符制表位和 C030 对应错位。小数点制表、默认制表网格、RTL/竖排、换行后的续行、目录前导符与其余原稿印章／跨页布局不从本组结论外推。最终结果与运行信息见 `evidence/word-explicit-tabs-20260924/`。
