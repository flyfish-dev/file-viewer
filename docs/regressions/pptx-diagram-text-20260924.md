# PPTX 独立文本区域与 SmartArt 标签布局

## 根因与修复

缓存绘图的文本变换原先只读取旋转而忽略独立偏移与宽高，段落换行也沿用整块图形宽度；单个缓存形状未转换为数组时会被跳过。现在文本层和段落分别使用有效文本区域，绘制层的形状坐标保持原值，缺失的文本属性继承形状坐标，无效区域不参与换算。

C016 的六个标签还有一项不同根因：缓存文本区域与整块圆形区域相同，但原稿布局定义另有六个隐藏文本节点。现在通过模型关系和 `moveWith` 查找配对文本节点，在已支持的 composite 布局、直接父宽高比例约束和明确节点数量分支中求得文本区域。换算保留实际缓存形状的拖动偏移和横纵缩放，不使用文件名、文字、模板名称、预设坐标或扇区中心近似。

这是约束求解的有限子集，不是完整 SmartArt 布局引擎。已有独立缓存坐标优先；不支持的算法、模糊的约束、间接引用、旋转/翻转、过深结构或无有效模型关系均保持原缓存。不改变原始文件、依赖、锁文件或版本。

## 验证

`verify-diagram-text.mjs` 默认 19 项，指定 C016 时 23 项。10 项单元检查覆盖独立轴比例、拖动、缓存优先、关系配对、无效约束、变换保护和无副作用；实际生产 Worker 与公开 `PptxViewer.open` 在 DPR 1/2 下检查文本区域、段落换行、单个缓存形状、反复打开和销毁。

C016 SHA-256 为 `ff4ac0df803b5d07603e8b44c7759e275d1502506f72e2ef33e1f4de4b9ee5c3`。独立 XML 读取器计算六个文本节点的左右/上下边界与宽高，逐一与真实 DOM 比较，允许低于 0.12 CSS 像素的子像素取整误差；额外检查六个区域不重叠。报告只记录中性编号、哈希、数量和几何。截图默认仅生成式文档；`PPTX_DIAGRAM_SCREENSHOT_ORIGINAL=1` 仅用于本地原样检查，不提交该截图或正文。

```bash
pnpm --filter @file-viewer/core build
pnpm --filter @file-viewer/pptx build
PPTX_DIAGRAM_ORIGINAL=/path/to/C016.pptx \
  node packages/renderers/pptx/scripts/verify-diagram-text.mjs
```

生产 Worker 必须重新构建并同步到部署。原样其他字体、形状、高级 SmartArt 排列与全文保真不因本组检查通过而自动结项。
