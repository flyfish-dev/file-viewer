# Word 绝对缩放与可测视口适配

## 已复现的通用缺陷

1. 窄容器中的响应式比例与用户倍率被分别截断、取两位小数，导致公开缩放接口不能达到标称 300%，小数缩放也被二次量化。现在只限制最终显示比例为既有的 24%～300%，保留内部精度，缩放按钮、状态和实际元素变换一致。
2. 流式 DOCX 和旧式 Word 适高采用固定 A4 高度，而不是当前内容高度。现在适配读取未缩放内容的真实高度；打印纸张仍由既有导出路径计算，不将长文档内容高度当作纸张高度。
3. 零、负数、非有限视口尺寸会被回退值替换并返回适配成功。现在区分缺省值与无效显式值；隐藏或不可测容器返回 `unmeasurable`，不改变缩放。显示后重新请求即可适配。非法缩放请求不修改状态或 DOM。

DOCX 和旧 DOC 两条实际渲染路径使用同一尺寸校验规则，不以文件名或正文特判。未修改公共接口、缩放边界、响应式倍率保持策略、运行依赖、锁文件、引擎补丁或静态 Worker。

## 验证

11 项新增单元测试；Word 包构建累计 97 项单元检查。浏览器生成式检查 55 项，加入 C053、C054、C069 原样后共 109 项，在 DPR 1/2 下运行。原件首先匹配 SHA-256；DOCX 实际 Worker 必须返回 `parsed`，正文再与独立 XML 内容逐字校验。C053/C054 本组仅检查正文与缩放，不据此结清链接和嵌入 HTML 的安全专项。

覆盖 300px 窄容器、24%/300% 上下界、小数比例、缩放按钮、无效输入、流式适高、隐藏恢复、响应式往返尺寸和卸载。比例容差 1e-8；实际渲染宽度误差小于 0.002 CSS 像素。修复前须在相同脚本的窄容器最大缩放断言失败，不能仅凭任意异常当作复现。

```bash
pnpm --filter @file-viewer/core build
pnpm --filter @file-viewer/doc build
pnpm --filter @file-viewer/renderer-word build
WORD_ZOOM_CORPUS_DIR=/path/to/neutral-originals \
  node packages/renderers/word/scripts/verify-zoom-fit.mjs
```

指定原样目录时缺件或哈希不符即失败；不指定时只执行生成式检查。证据见 `evidence/word-zoom-fit-20261006/verification.json`。这些是相关包和明确交互的验收，不代表完整工作区发版、原稿全部跨页保真或目标 WebView 验收。
