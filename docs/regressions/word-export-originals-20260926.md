# Word 图表段落导出与原样补充验收

## 两项实际缺陷

1. 图表通过 DOM 构造放在段落里的 div 中。直接序列化再作为 HTML 解析时，div 开始标签会结束外层段落，产生多余空段落、改变字体继承，并把后续内容向下推。C052 原稿的第一个图表在导出后比未缩放预览下移约 20.8 CSS 像素，即使最终纸张仍为 A4，也不能认为打印正确。
2. 流式打印把页面高度强制设为 A4 默认值，未使用原稿纸张高度。以 Letter 原稿为例，宽度保留 Letter 而高度变成 A4，造成错误的物理纸张。

修复只作用于 Word 导出边界。克隆时把段落内部的 HTML div 改为可合法嵌入段落的 span，保留计算后的 display、字体、颜色、尺寸及原有属性，仍使用原始 SVG 图表；不栅格化图表、不移除图表内容、不改变线上预览 DOM。SVG foreignObject 内部的独立解析上下文不转换。流式打印从页面最小纸张高度读取实际值，内容总高度和预览缩放不作为纸张高度。无法测量时仍使用原有后备值。

没有修改公共 API、运行依赖、锁文件、DOCX 引擎补丁、静态 Worker 或原文件。回退只需撤销本次 Word 导出辅助模块及调用点。

## 原样补充验收

对 C007、C011、C042、C052、C055、C064、C066、C071 的原文件先核对 SHA-256，再独立读取 OOXML 内容与关系。实际 Word renderer 必须收到真实 Worker 的 parsed 响应，不能以回退主线程代替通过。

| 原稿 | 这次确认的具体结果 |
| --- | --- |
| C007 | 使用 .doc 后缀的 OOXML 正确路由，原始正文逐字完整。 |
| C011 / C071 | 原有图表进入渲染，系列、数据点索引和柱高比例按源缓存复核；未误计为本次新增缺陷。 |
| C042 | 四页在宽/窄宿主及往返缩放时保持居中；正文、单元格和七张内嵌图片保留。 |
| C052 | 两种图表及全部数据保留；导出后图表坐标、原始页边距、正文和一页 A4 的实际打印 PDF 验证通过。 |
| C055 | 原稿图片按嵌入资源原始字节加载并解码，正文完整。 |
| C064 / C066 | 正文逐字、页内图片与表格数量、宽窄适配、往返缩放和卸载复测通过。 |

八份原稿在 DPR 1/2 下检查正文哈希、表格网格、嵌入图片字节及解码、图表系列和数值、1000→420→1000 像素宿主、100%/50%/200%/88%/100% 缩放和 Worker 清理，共 83 项。C052 的实际打印文件只记录页数、MediaBox 和哈希，不发布原稿输出。

## 可复现检查

```bash
pnpm --filter @file-viewer/core build
pnpm --filter @file-viewer/doc build
pnpm --filter @file-viewer/renderer-word build
node packages/renderers/word/scripts/verify-paragraph-export.mjs
WORD_ORIGINAL_CORPUS_DIR=/path/to/neutral-originals \
  node packages/renderers/word/scripts/verify-remaining-originals.mjs
```

原样目录按 `test/remaining-originals/identities.json` 的编号及扩展名放置文件。缺少原件会失败，不静默跳过。脚本工具依赖沿用根工具链、Word、PPTX（esbuild）与 PDF（pdf-lib）包；不新增安装依赖。

生成式检查包含 37 项实际 Worker/预览/导出/Chromium 打印检查，覆盖流式与固定分页、两档 DPR、三档缩放、再次 HTML 解析和 Letter 纸张。修复前必须在多余段落目标断言失败；修复后与预览的图表和段落几何逐项匹配。新增 12 项单元检查，Word 包累计 86 项。已有 C037 合并边框21项、VML57项、DOCX引擎11项、容器4项及六套DOC回归均保持通过；最终以附带的实际执行报告为准。

## 结项边界

本组结清以上原件已经给出的具体内容、居中、图表与导出偏移问题。几何相等验证的是同一渲染器预览和 HTML/打印转换不回退，不是与桌面应用所有字体和分页逐像素等价。真实打印驱动、iOS/企业 WebView、未提供原件的场景及其他尚未覆盖的跨页布局不得据此自动标为通过。所有公开证据仅包含中性编号、数值、哈希和生成式截图。
