# Word 网格段落的行内字体度量

## 根因与修复

启用文档行网格、采用自动行距的段落将 `max(自动行距, 网格行距)` 写成段落的已解析 CSS 长度。行内文字继承该固定长度后，较大字号和上下标的自然上升部、下降部及基线移动无法完整贡献行高。后续段落的底纹可能盖住前段文字；仅比较文字与文字的矩形，会遗漏这种绘制遮挡。

保留段落原来的自动行距和网格最小值，让普通行内文字及上下标使用字体引擎的自然行内度量。明确的固定行距、关闭网格、默认不启用网格的表格单元格、独立文本框、SVG、定位对象及显式行内行高不被改写。没有新增字号阈值、文件名或正文特判，不改原稿内容。

同时修复段落最小高度以无单位数值比较不同 CSS 单位的问题；例如 20pt 不能因为数值小于 20.8px 而被缩短。采用带单位的 `max()` 保留两者约束。

## 原样验证

C005 SHA-256：`0b6a601d5c98fb9d543a0baf4afce712f79831710ca6de4a383a1f69c89428a8`。独立读取 XML，保留 4,951 个文字字符及一个真实行内制表符；DOM 将制表显示为空白，比较的是归一化后的 4,952 字符序列。底纹绘制矩形与前段文字矩形按横向交集检查，避免将不存在字符丢失误写为丢字修复。

本地旧引擎的底纹向上覆盖前段约 9.20 个未缩放 CSS 像素；修复后不再覆盖。页数由实际字体、可用宽度和恢复后的行高决定，不硬编码原文件缓存页数，也不将当前环境的页数当作桌面应用参考。

## 回归与集成

`node --test test/docx-grid-metrics/inline.test.mjs` 检查自然行内度量的适用边界。`DOCX_GRID_ORIGINAL=/path/to/C005.docx node scripts/verify-docx-grid-metrics.mjs` 在 DPR 1/2、流式/分页、五档往返缩放、实际 Worker 和 HTML 导出下检查原文、遮挡、几何与清理。默认使用生成式文档；指定原件时增加只读原样检查。截图只发布生成内容。

使用仓库已有的五入口 pnpm 补丁机制集成，不在运行时替换原型。`scripts/prepare-docx-grid-metrics.mjs` 从固定哈希基线重建补丁并核对五个入口的字节；同时更新锁文件中的补丁身份、Worker 缓存版本和静态 Worker。必须重新安装声明的补丁并更新部署中的 DOCX Worker，单独安装未修补的 npm 旧包不会得到修复。

此批修复行网格下的自然字体度量及混合单位最小高度；不是全部文档的字体匹配、逐行网格吸附或打印驱动验收。相关构建、冻结锁安装及原样运行结果以 `evidence/docx-grid-metrics-20260924/verification.json` 为准，未运行的验证不计为通过。
