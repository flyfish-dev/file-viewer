# Sponsor File Viewer

File Viewer keeps private Office, PDF/OFD, CAD, archive, email, 3D, media, and data files in the browser instead of requiring another upload or conversion service. The public project remains Apache-2.0 open source.

> If File Viewer has saved your team implementation time, server cost, or repeated compatibility work, sponsorship is a direct way to return a small part of that value to ongoing maintenance.

- [Sponsor through GitHub](https://github.com/sponsors/wybaby168?metadata_campaign=file-viewer-docs-en) — one-time or recurring support.
- [WeChat / Alipay](https://dev.flyfish.group/sponsor?source=file-viewer-docs) — convenient one-time support for domestic users.
- [Enterprise support](https://dev.flyfish.group/shop) — private deployment, scoped compatibility work, contracts, and committed response expectations.

## Why sponsorship matters

A successful demo is only the beginning. Long-term maintenance is dominated by the cases that are difficult to reproduce: Office files produced by different applications, CAD vendor extensions, damaged or encrypted archives, browser regressions, Worker and WASM loading paths, embedded fonts, old framework builds, and offline deployment constraints.

Sponsorship helps preserve focused maintenance time for the public project instead of forcing every difficult compatibility problem to wait for spare time.

## What sponsorship funds

## What should I contribute?

There is no required amount or fixed tier. A one-time “thanks, this saved me a headache” tip is useful; recurring support helps even more because maintenance time becomes easier to plan.

Choose whatever feels reasonable for the time and trouble File Viewer saved you. If your company needs an SLA, contract, invoice, confidential file handling, or a defined deliverable, use enterprise support instead. A larger donation still does not buy issue priority.

## Clear boundaries

Sponsorship supports the project; it is not a hidden paid issue queue.

- It does not guarantee that a requested format, feature, or bug fix will be accepted or completed by a specific date.
- It does not include private consulting, confidential file analysis, or a service-level agreement unless explicitly included in a published tier or enterprise agreement.
- It does not change the Apache-2.0 license or restrict access to public features and documentation.
- Sensitive files should never be attached to a public issue. Use sanitized samples or an appropriately scoped private engagement.

## Other valuable ways to help

Financial support is not the only useful contribution. Sanitized failing samples, minimal reproductions, accurate bug reports, documentation improvements, translations, case studies, and sharing the project with teams that need private file preview all materially improve File Viewer.
