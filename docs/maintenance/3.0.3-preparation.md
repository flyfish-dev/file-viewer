## 发布效率与当前阻塞

打包和 registry 下载/比对默认四路并发；GitHub publisher 先核验全部不可变产物，再按依赖层以三路上传、六路查询推进。上一层在 registry 可见且完整性一致后才能启动下一层。失败后停止新调度并等待已开始的进程结束；续跑只跳过字节相同的已发布版本，不因传播延迟或认证失败重新分配版本号。20 项 publisher 故障、完整性、依赖顺序和续跑测试接入 workflow 与治理门，完整演练和生产 postcheck 未被删减。

截至 2026-09-08，DWF、DOCX 与 styled-exceljs 的构建/测试及打包 dry-run 已通过，但 npm 未接受其发布身份。DWF 的[只读授权检查](https://github.com/flyfish-dev/dwf-viewer/actions/runs/34180986841)失败，DOCX 的[正式发布](https://github.com/flyfish-dev/docxjs/actions/runs/34180973609)和 styled-exceljs 的[正式发布](https://github.com/flyfish-dev/styled-exceljs/actions/runs/34182052946)停在 npm 上传步骤（E404）。dry-run 不能证明授权已配置。DWF 0.6.7 的 GitHub Release 存在也不表示 npm 已发布；CAD 0.8.2 继续等待 DWF，未越过依赖顺序。不要循环触发本机 security key，也不要读取凭据来绕过 passkey。

主仓版本尚未冻结，3.0.3 还没有正式演练、发布或部署。当前本地 Demo 是隔离候选，使用了尚未发布的上游包；源码、候选包和旧准备快照必须分开保存，不能把旧 Demo 或候选检查当作新版本上线凭据。
