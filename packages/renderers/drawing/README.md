# @file-viewer/renderer-drawing

[English](https://github.com/flyfish-dev/file-viewer/blob/main/packages/renderers/drawing/README.md) · [简体中文](https://github.com/flyfish-dev/file-viewer/blob/main/packages/renderers/drawing/README.zh-CN.md)

Standalone Draw.io, Excalidraw, Mermaid, and PlantUML renderer for Flyfish File Viewer.

## Highlights

- Uses the bundled diagrams.net offline viewer for `drawio` / `dio` files.
- Renders `excalidraw` as a stable read-only SVG through `roughjs` by default. If the runtime provides the official `@excalidraw/excalidraw` ESM module, the renderer tries `restore` and `exportToSvg` first and falls back automatically.
- Lazy-loads the official `mermaid` renderer for `mermaid` / `mmd` files and outputs theme-aware SVG.
- Keeps `plantuml` / `puml` files fully offline by default with an SVG source preview; configure `options.drawing.plantumlServerUrl` for full PlantUML SVG rendering through a self-hosted endpoint. When that endpoint is unavailable, the renderer still falls back to the offline preview instead of a blank view or broken image.
- Mermaid and PlantUML previews use `@panzoom/panzoom` for drag panning, Ctrl/Command wheel zoom, and common toolbar zoom sync.
- Supports unified zoom, print, HTML export, and `options.drawing` self-hosted asset configuration.
- Ships as an independent renderer package for applications that only need drawing preview.
- `@file-viewer/core` no longer bundles the drawing renderer and no longer depends directly on `@excalidraw/excalidraw`, `mermaid`, `plantuml-encoder`, `@panzoom/panzoom`, or `roughjs`.

## Usage

```ts
import { createFileViewerCore, createFileViewerRendererRegistry } from '@file-viewer/core';
import { drawingRenderer } from '@file-viewer/renderer-drawing';

const registry = createFileViewerRendererRegistry({
  renderers: [drawingRenderer],
});

const viewer = createFileViewerCore({
  target: document.querySelector('#viewer')!,
  rendererRegistry: registry,
});
```

See the [official on-demand renderer guide](https://doc.file-viewer.app/guide/on-demand-renderers) for production setup.

## Opt-in BPMN (experimental)

BPMN 2.0 uses the separate `/bpmn` entry. It does not extend the default
`drawingRenderer`, existing presets, or Full. Install the optional engine and
register the plugin explicitly:

```sh
npm install @file-viewer/core @file-viewer/renderer-drawing bpmn-js@18.28.0
```

```ts
import { createFileViewerCore, createFileViewerRendererRegistry } from '@file-viewer/core';
import { bpmnRenderer } from '@file-viewer/renderer-drawing/bpmn';

const viewer = createFileViewerCore({
  target: document.querySelector('#viewer')!,
  rendererRegistry: createFileViewerRendererRegistry({ renderers: [bpmnRenderer] }),
});
```

- Renderer id `bpmn`, extension `.bpmn`, and `presets: []`.
- The official read-only bpmn-js Viewer renders events, tasks, gateways, pools,
  lanes, message flows and subprocesses. Files with several BPMNDiagram elements
  have a diagram selector.
- Diagram and Source views preserve the decoded original XML, including its BOM,
  line endings, comments and extensions. Source is not regenerated by the engine.
- The common zoom provider and local toolbar support pan, arrow keys,
  Ctrl/Command wheel zoom, fit and actual size. Source zoom changes font size;
  switching back preserves diagram pan and zoom.
- Files without BPMN DI layout show their source with an explanation. Malformed
  XML, DOCTYPE declarations and import errors also retain source. Partial imports
  display a warning; the viewer does not invent missing layouts.
- Process scripts are data and are never executed. External or variable color
  paints are removed only from the render copy. Original XML remains unchanged.
  The engine and CSS are bundled locally with no CDN, remote parsing or font fetch.
- Official CSS is injected into the current container, including Shadow DOM.
  Hosts need no separate CSS import. `unmount()` removes the zoom provider,
  listeners and observer, and destroys the engine after any pending import ends.
- The default input limit is 20 MiB. This entry does not advertise printing, HTML
  export, editing, or process execution.

Use `createBpmnRenderer({ initialView: 'source', maxFileBytes: 20 * 1024 * 1024 })`
to customize the plugin, or render directly into a container with an explicit height:

```ts
import { renderFileViewerBpmn } from '@file-viewer/renderer-drawing/bpmn';

const instance = await renderFileViewerBpmn(buffer, target, { options: { locale: 'en-US' }, signal });
await instance.ready;
instance.setView('source');
const originalXml = instance.getSource();
const diagrams = instance.getDiagrams();
// await instance.selectDiagram(diagrams[0].id);
await instance.unmount();
```

`ready` settles after an import attempt; file errors appear in the viewer while
source stays accessible. `getDiagrams()` returns `id`/`name` descriptors and
`selectDiagram(id)` queues diagram switches. `context.signal` cancels the instance.
